# subday — лендинг

Страница-визитка subday.app: одностраничный сайт с формой заявки для заведений
и админкой для правки содержимого.

Это **не** приложение subday. Приложение живёт отдельно, в репозитории
[arnigpk/subday](https://github.com/arnigpk/subday): другой код, другие сборки
под магазины, другая схема в базе. Общего у проектов только сервер, экземпляр
Postgres и рантайм edge-функций.

## Что внутри

- **Сайт** — секции собираются из содержимого в базе, порядок и видимость
  задаются в админке. Два языка, RU и KZ, у каждого свой черновик и своя
  опубликованная версия.
- **Админка** `/admin` — редактор секций, заявки партнёров, загрузка картинок,
  настройки Telegram-уведомлений, смена пароля.
- **Форма заявки** — уходит в edge-функцию `submit-lead`: та кладёт заявку в
  базу и, если включено, шлёт уведомление в Telegram.

## Стек

Vite + React + TypeScript, Tailwind, framer-motion, React Query.
Данные — Supabase на своём сервере (`api.subday.app`).

## Локально

```bash
npm install
npm run dev
```

Нужен `.env` с `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` — оба
значения публичные, они и так уезжают в браузерный бандл.

Проверки:

```bash
npm test
```

## База

Таблицы сайта лежат в отдельной схеме `landing`, а не в общей `public`: имена
`user_roles`, `app_role` и `has_role` уже заняты приложением, где роли совсем
другие. Схема задаётся один раз в `src/integrations/supabase/client.ts`
(`db: { schema: 'landing' }`), поэтому запросы в коде пишутся как обычно —
`from('site_pages')`.

Схема целиком — в `supabase/migrations/20260815000000_landing_schema_selfhosted.sql`.

| Таблица | Что хранит |
|---|---|
| `site_pages` | содержимое страницы: черновик и опубликованное, RU и KZ |
| `site_settings` | настройки Telegram-уведомлений |
| `partner_leads` | заявки с формы |
| `user_roles` | кто администратор сайта |

Заявку может оставить любой гость, а читать заявки может только администратор —
это разведено политиками RLS.

## Выкладка

Собранная статика лежит на сервере в `/var/www/landing`. В nginx включён
`gzip_static`, поэтому после каждой выкладки статику нужно пересжать:

```bash
find /var/www/landing -type f \( -name "*.js" -o -name "*.css" -o -name "*.html" \) -exec gzip -9 -k -f {} \;
```

Иначе рядом с новыми файлами останутся старые `.gz`, и браузеры будут получать
именно их.
